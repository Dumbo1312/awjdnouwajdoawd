# UEFITool debloat catalogue
# ==========================
#
# What the Debloat dialog offers to remove from an opened firmware image.
#
# READ THIS BEFORE ANYTHING ELSE
# ------------------------------
# Removing firmware modules does NOT increase frame rate. Not one entry in
# this file will give you a single extra FPS. By the time Windows is running,
# none of this code is executing any more. What removal actually buys you is:
#
#   * a shorter POST, sometimes noticeably so for the network stack and CSM
#   * less code running before the OS, so less attack surface
#   * free space in the BIOS region, which matters when adding things
#
# What it can cost you is the machine not booting. Firmware modules have
# dependencies, and a module that looks useless may be dispatched by something
# else, listed in an apriori file, or referenced by GUID from code this tool
# cannot read. The dialog runs a cross-reference and an apriori check before
# it lets you remove anything, and it still cannot prove a removal is safe.
#
# If your board has Intel Boot Guard or AMD Platform Secure Boot enabled, a
# modified image will not boot at all. See docs/risks-and-recovery.md.
#
# Nothing in here is selected by default, and nothing is removed until you
# say so twice.
#
# Some categories are marked #!protected. Those are boot critical: the
# compatibility support module, storage controller drivers, the firmware's own
# flash write path, and AMD platform initialisation. They are still listed, so
# you can see what your image contains, but they have no checkbox and this
# tool will not remove them. Breaking the boot path is not something that
# should be one careless click away.
#
# FILE FORMAT
# -----------
# Directives, all starting with '#' so other tools read the file as comments:
#
#   #!category <id>      start a category
#   #!label <text>       category name shown in the dialog
#   #!risk <word>        low, medium or high
#   #!impact <text>      what removing this category actually gains you
#   #!note <text>        caveats, repeat the directive for more lines
#   #!platform <name>    Intel, AMD or Any; the dialog dims non matching ones
#   #!requires <text>    a condition you must have checked yourself first
#   #!protected          the category is listed so you can see what is in your
#                        image, but nothing in it ever gets a checkbox
#
# Entries, one per line:
#
#   N <text>   a module whose own name in the image contains <text>
#   G <guid>   a module with this file GUID
#
# Everything after the first field is the friendly description.
#
# Name matching is the primary mechanism on purpose. A UEFI module carries
# its own name in a user interface section, so matching on it reads what is
# actually in your image rather than trusting a list of GUIDs that differ
# between vendors and BIOS versions. A name that matches nothing simply does
# not appear in the dialog, which is the safe failure.


#============================================================================
#!category network-boot
#!label Network boot stack (PXE, HTTP boot, iSCSI)
#!risk medium
#!platform Any
#!impact Usually the largest single POST time saving. Often a second or more
#!impact on boards that probe the network at every boot.
#!note Remove only if you never boot this machine from the network and never
#!note need iSCSI or HTTP boot. The onboard network card still works normally
#!note under the operating system: this is the firmware's own TCP/IP stack,
#!note not the card's driver.
#!note On a corporate or managed machine, PXE is often how it gets reimaged.
#============================================================================

N Ip4Dxe              IPv4 stack

#============================================================================
#!category csm-legacy
#!label Compatibility Support Module (legacy BIOS boot)
#!protected
#!risk high
#!platform Any
#!impact Nothing, because this tool will not remove it.
#!note Protected. CSM sits directly on the boot path, and the failure mode for
#!note getting it wrong is a machine that does not boot at all rather than one
#!note that boots a bit slower.
#!note It is listed so you can see what your image carries. Turning CSM off in
#!note setup gives you the pure UEFI boot path without touching the image at
#!note all, which is what you actually want, and a CMOS clear undoes it.
#!note Removing it would also remove legacy option ROM support, so any add-in
#!note card without a UEFI option ROM would stop initialising.
#============================================================================

N CsmVideo            Legacy video option ROM support
N CsmBlockIo          Legacy block IO over the CSM
N LegacyBios          Legacy BIOS protocol implementation
N AmiLegacy           AMI legacy support module

N LegacyRegion        Legacy memory region handling
N LegacyInterrupt     Legacy interrupt handling
N Legacy8259          8259 interrupt controller support
N BiosVideo           Legacy BIOS video driver

N Ps2Mouse            PS/2 mouse driver, only if you have no PS/2 ports in use
N Ps2Keyboard         PS/2 keyboard driver, only if you have no PS/2 ports in use

#============================================================================
#!category unused-storage
#!label Storage controllers and RAID
#!protected
#!risk high
#!platform Any
#!impact Shorter POST, because each controller driver probes its bus.
#!note Protected. This is the easiest category in the file to get wrong, and
#!note the way it goes wrong is that the machine stops finding its boot disk.
#!note Removing the driver for the controller your operating system lives on
#!note leaves nothing to boot from and nothing to recover with except the
#!note flash programmer.
#!note Listed so you can see what your image carries.
#!note A third party controller driver is present because the board has that
#!note chip. The usual reason to remove one is a board revision that shares a
#!note firmware image with a higher model that does have the chip.
#!note Never remove the driver for the controller your operating system is
#!note installed on. If you are unsure which that is, do not use this
#!note category at all.
#============================================================================

N MarvellSata         Marvell SATA controller driver
N AsmediaSata         ASMedia SATA controller driver
N Asm106x             ASMedia SATA controller driver

#============================================================================
#!category flash-path
#!label The firmware's own flash write path
#!protected
#!risk high
#!platform Any
#!impact Nothing, because this tool will not remove it.
#!note Protected. These are the drivers and system management handlers that
#!note write to the SPI chip. They are how the board updates itself, how a
#!note vendor recovery tool writes a known good image back, and on some boards
#!note how the firmware saves its own settings.
#!note Removing them can leave a machine that boots perfectly and can never be
#!note updated or recovered by software again, which is the worst kind of
#!note mistake: it does not show up until the day you need it.
#!note Listed so you can see what your image carries.
#============================================================================

N FlashDriver         SPI flash write driver
N SmiFlash            Flash access through system management mode
N FlashSmi            Flash access through system management mode
N SecFlash            Authenticated flash update path
N ReFlash             Firmware recovery and reflash path
N AmiPspFlash         AMD PSP flash access
N RpmcSmm             Replay protected monotonic counter, used by secure flash
N FvbService          Firmware volume block services, the NVRAM write path
N SpiSmm              SPI controller system management handler
